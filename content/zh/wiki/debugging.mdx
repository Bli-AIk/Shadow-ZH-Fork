# 调试 [debugging]

<Box>

开发过程中充满了测试和**错误**。

我们希望让这一过程尽可能快速、简单，所以来看看 Kristal 的**调试工具**吧。

</Box>

<Box>
## 开始使用 [getting-started]

在逐一介绍调试工具之前，我们需要确保它们全部都已**启用**。

打开你的 `mod.json`——如果看到 `"dev": true`，就说明已经准备好了。如果没有，请将其改为 `true`（或添加这一项）并保存。

---

还有一件事。

前往 Kristal 的选项菜单，进入键盘控制。向下滚动，直到看到下面四项：

<>![图片](/wiki/debug_controls.png)</>

这些是我们接下来要使用的其他调试工具的默认按键绑定。

注意其中一些绑定使用的 `` ` ``（反引号）。它看起来很像 `` ' ``（撇号），但两者并不相同。**务必不要混淆！**
</Box>

<Box>
## 调试快捷键 [debug-hotkeys]

调试快捷键相当直接。按下某些按键，就会发生一些事情。
这些事情通常会帮助你更快地完成测试，例如完全恢复生命值、恢复 TP，或者干脆直接加速游戏。

以下是调试按键及其功能的完整列表：

- `Ctrl+R` 快速保存游戏，然后重新加载你的项目。你会回到之前所在的世界/地图以及对应状态。
- `Ctrl+Shift+R` 不进行快速保存，直接重新加载游戏。你会从上次保存的位置开始。
- `Ctrl+Alt+R` 从新文件重新加载游戏。
- `Ctrl+M` 暂停/恢复游戏内音乐。
- `Ctrl+N` 切换穿墙模式。
- `Ctrl+G`（快进按键绑定）切换快进。
- `Ctrl+H` 将队伍生命值完全恢复。
- `Ctrl+K` 完全恢复 TP。
- `Ctrl+B` 立即让你死亡。

下面两个快捷键仅在战斗中有效：
- `Ctrl+F` 结束所有正在进行的波次。
- `Ctrl+Y` 立即赢得战斗。

下面这些快捷键使用功能键——在某些设备上，你需要同时使用 `Ctrl` 或 `Fn`，Kristal 才能检测到输入。
- `F2` 切换快进。
- `F3` 打开本网站！
- `F4` 启用全屏。
- `F6` 启用调试渲染。
</Box>

## 调试菜单 [the-debug-menu]

调试的有趣部分从这里开始！

按下 `` Ctrl+` ``（或你的调试菜单按键绑定）打开调试菜单。它应该会以覆盖层的形式显示在游戏窗口上：

<>![图片](/wiki/debug_menu.png)</>

这里有许多选项和子菜单！在屏幕底部，你会看到当前选中选项功能的简短说明。

许多由调试快捷键切换的功能也会出现在这里！

---

引擎的一些设置位于 Engine Options 中，例如帧率选项和 FPS 显示开关。

最好使用这个功能**测试多种帧率**，确保你的同人游戏在不同帧率下都能正常运行，也就是确保所有玩家都能正常游玩。（只测试 30fps 和 60fps，就足以看出代码是否与帧率无关。）

此菜单中的其他选项是一系列便于调试和测试的实用功能。尽管试着操作一下吧！

当然，这里还有**仅限主世界**和**仅限战斗**的菜单。记得在两种场景中都查看调试菜单，充分发挥它的潜力！

---
### 调试渲染 [debug-rendering]

调试菜单中有一项功能叫作**调试渲染**。（好吧，其实它也属于调试快捷键。）

调试渲染主要用于显示碰撞；此外，在战斗中还会显示状态和快捷键信息：

<>![图片](/wiki/debug_render_battle.png)</>

这本身就很有用，但这些信息还可以帮助你用一些可能没想到的方式进行调试。

大多数存在的对象都有某种碰撞体。这包括我们通常看不见的对象，例如许多**事件**。

借助调试渲染，我们可以通过碰撞体看到这些原本不可见的对象：

<>![](/wiki/debug_render_world.png "密切注意墙上的粉色方块！那是一个我们通常看不见的可交互对象。")</>

事件（主世界对象）会显示为**粉色**。如果事件所在位置没有粉色轮廓，说明存在某种加载问题。

反过来，如果碰撞箱存在，那么我们就可以*排除*加载问题，并确定问题与对象本身的运行有关。

像这样缩小问题范围，会更容易追溯 Bug 的源头并将其解决。永远不要低估一堆彩色形状轮廓的力量！

如果你想为调试渲染器绘制自己的内容，可以在任意绘制代码中检查 `DEBUG_RENDER` 全局变量，并据此有条件地绘制调试信息。

---

## 对象选择器 [the-object-selector]

对象选择器就是用来选择对象的。为什么？其实理由有很多！

要切换对象选择器，请按下 `Ctrl+O`（或你的对象选择按键绑定）。你应该会看到屏幕上出现文字，以确认对象选择器已启用：

<>![图片](/wiki/object_select.png)</>

使用对象选择器时，你可以选择是否让游戏在它背后继续运行。

你在调试菜单中可能见过**选择对象时暂停**。这个选项就是控制该行为的。

大多数时候，你可能会想让游戏在对象选择器后方继续运行；但对于临时出现的、移动很快的小型对象来说，暂停会很有用，所以**别忘了这个选项！**

---

在对象选择器中，你可以使用**鼠标光标**选择对象。

将鼠标悬停在对象上时，你会看到所有对象的调试矩形（不是碰撞箱！）以及它们所属的 Class。

点击某个对象，然后……

<>![图片](/wiki/object_select_kris.png)</>

好多信息！我们来逐项拆解。

首先是“Selected”显示。这是我们悬停时已经看到过的信息的重复：被选中对象的 Class。

接下来是这个对象原点的 `x` 和 `y` 坐标，**相对于它的父对象**。

紧接着是它的**屏幕位置**，这个位置相对于**游戏窗口的左上角***。

（* 不包括边框或任何窗口缩放。游戏窗口始终按 640x480 处理。）

这里剩下的数据就是**调试信息**。

你可能在许多对象上见过名为 `getDebugInfo()` 的方法——它就是用来提供这些信息的！

下面是 `Player` 对象在其 `getDebugInfo` 中输出的全部内容。我们可以查看源代码来确认：

```lua
function Player:getDebugInfo()
    local info = super.getDebugInfo(self) -- （Player 的父类也有要显示的调试信息，这一行会让它使用这些信息）
    table.insert(info, "State: " .. self.state_manager.state)
    table.insert(info, "Walk speed: " .. self:getBaseWalkSpeed())
    table.insert(info, "Current walk speed: " .. self:getCurrentSpeed(false))
    table.insert(info, "Current run speed: " .. self:getCurrentSpeed(true))
    table.insert(info, "Run timer: " .. self.run_timer)
    table.insert(info, "Hurt timer: " .. self.hurt_timer)
    table.insert(info, "Slide in place: " .. (self.slide_in_place and "True" or "False"))
    return info
end
```

作为开发者，你可能也想为自己的许多对象添加调试信息。

在这些对象的文件中，你同样可以定义 `getDebugInfo()` 函数。这个函数没有什么特别之处，以 `Player` 的实现为例应该很容易理解。

为了配合对象选择器，你可能还想知道如何修改对象的**调试矩形**。这些是专门用于对象选择器的碰撞箱。

如果默认调试矩形造成了问题，只需将下面这行快速添加到每个对象的 `init()` 函数中：

```lua
    self.debug_rect = { x, y, width, height } -- 将这些值替换为你希望调试矩形使用的形状
```

## 控制台 [the-console]

这是 Kristal 主要调试功能中的最后一项。

控制台是最灵活的调试工具。使用打开控制台的按键访问它，该按键是 `` ` ``。

你应该会看到控制台显示在游戏窗口上方：

<>![图片](/wiki/console_open.png)</>

控制台可以运行代码。如果你输入内容并按下 Enter，它就会立即运行：

<video controls preload="none">
    <source src="/wiki/console_explosion.mp4" type="video/mp4" />
    你的浏览器不支持此视频。
</video>

你可以在控制台中快速编写并运行代码来测试内容。不过要注意，在这个上下文中，你能访问的实用全局变量很少，因此会**大量**依赖 `Game`。

如果你直接输入了会报错的内容，控制台会输出错误，**而不会**让游戏崩溃。

另一个实用功能是 `=value` 语法。如果输入内容以 `=` 开头，它就会将该值作为输出显示在旁边：

<>![图片](/wiki/console_print.png)</>

这非常适合快速检查计算结果或变量值。

---

无法快速访问对象，而且总要使用 `Game`，实在很*烦人*。如果我们能解决这个问题呢？

<video controls preload="none">
    <source src="/wiki/console_explosion_neo.mp4" type="video/mp4" />
    你的浏览器不支持此视频。
</video>

什么！？

没错——对象选择器选中的对象可以**通过控制台访问**。你可以使用 `_` 下划线或 `selected` 这个单词来引用当前选中的对象。

这个交互让我们更容易快速检查对象的变量并运行代码。
