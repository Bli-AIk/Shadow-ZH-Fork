    ## 基础知识 [the-basics]
    ---
    在本教程中，你将全面了解 Kristal 中的事件、如何从 Tiled 配置它们，以及如何使用它们的一些示例。

    本教程稍微复杂一些。因此，你需要先理解一些基础概念。

    ### Tiled 属性 [tiled-properties]
    ---
    创建新事件时，可以通过事件的属性修改它的行为。

    为对象添加自定义属性时，必须确保在 Tiled 中使用的类型与代码中定义的类型一致。

    下表定义了 Kristal 类型与 Tiled 类型之间的转换关系：
    | Kristal（Lua） | Tiled |
    |---|---|
    |number|int \| float|
    |boolean|bool|
    |string|string|
    |array []||
    |any|int \| bool \| string|

    如你所见，数组不能直接在 Tiled 中定义，但我们可以使用另一套系统来定义这些字段。
    [查看教程](#text-tutorial)

    `any` 类型表示该属性的 Tiled 类型可以是 int、bool 或 string 中的任意一种。

    number 通常是 int（整数，即不带小数的数字），但有时也可以是 float（带小数的数字）。

    在本教程中，事件属性使用以下定义：**name: type = default**。

    `name` 是**自定义属性的名称**。

    `type` 是该属性的 **Lua 类型**。

    `default` 是**未在 Tiled 中定义该属性时**，它**将拥有的值**。
    如果属性没有这个参数，则表示该属性没有默认值。

    ## 文本教程 [text-tutorial]
    ---

    一些事件的文本属性通常定义为 string[]，也就是字符串数组。由于你无法直接在 Tiled 中创建数组，所以必须使用 Kristal 实现的自定义定义方式。

    使用这套系统，你可以创建一个文本框来显示文本，创建多个文本框来显示更多文本，或者让文本在玩家每次交互时发生变化。

    参考[编写文本教程](/wiki/writing-text)，了解这些字段应该填写什么值。

    根据你想要的用途，这些属性的语法也有所不同。

    ### 多个文本框 [multiple-textboxes]
    ---

    如果想显示的文本无法放进一个文本框，可以使用多个文本框显示全部文本。

    这需要使用多个自定义属性，每个文本框对应一个属性，语法如下：**textX**。
    X 是文本框的编号。

    例如，我们想创建一个显示以下文本的[可交互对象](#interactable)：
    - 文本框 1：* 看起来这只是一个洞。
    - 文本框 2：* 仔细一看，这是一个装满莎莎酱的洞。
    - 文本框 3：* 你决定不踩进这个洞里。

    要创建这个交互，我们需要创建一个可交互对象，并为它添加以下属性：
    - `text1`：* 看起来这只是一个洞。
    - `text2`：* 仔细一看，[wait:5]这是一个装满莎莎酱的洞。
    - `text3`：* 你决定不踩进这个洞里。

    ## 创建脚本 [making-scripts]
    ---
    脚本是可以在某些事件上执行的函数。它类似于过场动画，但拥有不同的参数，而且不需要使用过场动画系统。

    要创建脚本，请在 `/scripts/world/scripts` 中创建一个 `"file".lua` 文件。**file** 是脚本的名称，也是调用该脚本时使用的名称。

    在本例中，我们创建一个 test_script.lua，并将它存放在该目录中。然后需要编写将要执行的代码。

    你可以将以下代码作为自己脚本的占位模板。
    ```lua
    ---将要执行的函数
    ---@param event Event 执行此脚本的事件
    ---@param player Player 执行此脚本的玩家
    ---@param facing string 玩家面朝的方向。仅当脚本由可交互对象或 NPC 事件执行时设置
    return function(event, player, facing)
        -- 要执行的代码
    end
    ```

    如你所见，这个函数有多个参数，但具体参数会根据调用脚本的事件而变化。

    如果使用[可交互对象](#interactable)或[NPC](#npc)，函数会收到 `event`、`player` 和 `facing`。facing 会被设置为
    `"left"`、`"up"`、`"down"` 或 `"right"`。

    如果使用[脚本](#script)，函数会收到 `event` 和 `player`。

    如果使用[瓦片按钮](#tile-button)，则只有 `event` 会被设置。

    作为示例，我们来做点傻事：让 Kris 摆出 T 姿并播放一段滑稽的音效。

    ```lua
    ---将要执行的函数
    ---@param event Event 执行此脚本的事件
    ---@param player Player 执行此脚本的玩家
    ---@param facing string 玩家面朝的方向。仅当脚本由可交互对象事件执行时设置。可以是 "up"、"down"、"left" 或 "right"
    return function(event, player, facing)
        -- 将玩家精灵（本例中为 Kris）改为 t_pose 精灵
        player:setSprite("t_pose")
        -- 播放 Lancer 的 splat 音效
        Assets.playSound("splat")
    end
    ```

    创建一个[可交互对象](#interactable)并在其中添加自定义字段 `script`，值为 **test_script**，或者创建一个[脚本](#script)并为它设置相同的属性，即可执行这个脚本。

    ## 路径系统教程 [path-system-tutorial]
    ---

    路径用于定义主世界中某些对象的移动方式。简单来说，它是一系列点，对象会在这些点之间移动。

    要创建路径，创建一个名称以 `paths` 开头的新对象图层。然后使用 Tiled 的 **插入多边形工具（P）** 创建一个多边形。
    多边形的**周长**就是对象将要沿着移动的路径。别忘了给多边形添加**名称**，之后你需要通过它引用该路径。

    如果想创建圆形路径，使用 **插入椭圆工具（C）** 创建想要的圆形。路径就是椭圆的**圆周**。别忘了给它**命名**，因为之后需要通过名称引用这条路径。
    这种路径**不能用于过场动画**。

    路径的创建就是这些内容。现在来看看如何使用这套系统的一些示例。

    使用**插入多边形工具（P）**创建一个多边形，定义 NPC 要经过的路径，然后给路径**命名**。

    #### 在过场动画中使用路径 [using-paths-in-cutscenes]
    ---

    你**不能在过场动画中使用椭圆**作为路径，**只能使用多边形**。

    `WorldCutscenes` 使用路径让角色沿着定义好的路径行走或滑行。

    你可以在过场动画中使用以下函数调用路径：
    - [WorldCutscene:walkPath(chara, path, options)](/wiki/api/WorldCutscene#walkPath)
    - [WorldCutscene:slidePath(obj, path, options)](/wiki/api/WorldCutscene#slidePath)

    `walkPath` 和 `slidePath` 的主要区别在于，`walkPath` 会让角色播放行走动画，而 `slidePath` 只会移动对象。

    看起来很简单，对吧？不过，考虑到这些函数拥有许多选项，事情就没那么简单了。
    由于选项已经在 API 中定义好了，我会直接在示例中使用它们。

    首先，我会在 **room1** 组中创建一个新的过场动画，并将其命名为 **testing_paths**。

    文件位置为 `scripts/world/cutcenes/room1.lua`

    ```lua
    ---@param cutscene WorldCutscene 过场动画对象
    ---@param event Event 执行此过场动画的事件
    testing_paths = function (cutscene, event)
    end
    ```

    我们已经有了占位过场动画。现在来创建角色要使用的路径。
    我不想让路径循环，所以不会闭合这些多边形。

    这就是我创建的路径。

    ![](/wiki/path_tutorial_3.png)

    如你所见，我创建了一些相当奇怪的路径，只是为了好玩。我还创建了一个[脚本事件](#script)来执行这个过场动画，并为它设置了以下自定义属性。

    ![](/wiki/path_tutorial_4.png)

    现在可以实际编写使用这些路径的过场动画了。这是我最后写出的代码。

    ```lua
    --- 用于测试过场动画中路径的测试过场动画
    ---@param cutscene WorldCutscene 过场动画对象
    ---@param event TileButton 执行此过场动画的事件
    testing_paths = function (cutscene, event)

        -- 获取欢乐帮，因为我们要移动他们
        local kris = cutscene:getCharacter("kris")
        local susie = cutscene:getCharacter("susie")
        local ralsei = cutscene:getCharacter("ralsei")

        -- 检查 nil 总是有用的
        if kris and susie and ralsei then

            -- 我们要移动 Susie 和 Ralsei，所以需要让他们停止跟随 Kris
            cutscene:detachFollowers()

            -- 查看 walkPath 中的选项，了解这个表的含义
            local options = {
                facing = "right",
                speed = 4,
                snap = false
            }
            cutscene:walkPath(kris, "path_kris", options)
            cutscene:walkPath(ralsei, "path_ralsei", options)

            -- 查看 slidePath 中的选项，了解这个表的含义
            options = {
                facing = "right",
                time = 2,
                ease = "in-out-sine",
                snap = false
            }
            cutscene:slidePath(susie, "path_susie", options)

            -- 等待他们走完路径
            -- 如果为所有人使用 time，就能准确知道他们需要多长时间
            cutscene:wait(5)

            -- 只是添加一些有趣的文本
            cutscene:text("* What was that?", "concern_smile", ralsei)
            cutscene:text("* I don't know,[wait:5] I just wanted to do something fun.", "small_smile", susie)
            cutscene:text("* And...[wait:5] was it fun?", "concern_smile", ralsei)
            cutscene:text("* Not really...[wait:5] just nauseating.", "nervous_side", susie)
            cutscene:text("* .[wait:5].[wait:5].[wait:5]", "neutral", susie)
            cutscene:text("* .[wait:5].[wait:5].[wait:5]", "neutral_side", susie)
            cutscene:text("* Lets just go already.", "nervous_side", susie)

            -- 让跟随者重新跟上 Kris
            cutscene:attachFollowers()

            cutscene:wait(1)

        end
    end
    ```

    ## 可交互对象 [interactable]
    ---
    可交互对象是在玩家与其交互时激活脚本、过场动画或文本的对象，也就是玩家按下操作按钮（通常是 “Z” 键）时激活。

    这个 [`Event`](/wiki/api/Event) 应该是一个 `area`，因此请使用矩形创建它，并在 `objects` 图层上将其命名为 `interactable`。

    你可以使用它为主世界中的对象**添加氛围文本**。

    事件拥有以下属性：
    - `solid: boolean = false` -> 如果为 **true**，玩家会像撞到碰撞体一样与此对象发生碰撞。
    <br></br>如果为 **false**，玩家可以穿过该对象。
    - `cutscene: string` -> 与此对象交互时要启动的过场动画名称。
    记得使用 **group.name** 的格式命名。
    - `script: string` -> 与此对象交互时要执行的脚本文件名称。
    - `text: string[]` -> 玩家与对象交互时文本框中显示的文本。[查看该属性的教程](#text-tutorial)。
    - `setflag: string` -> 玩家交互时要设置为 `setvalue` 的旗标名称。
    使用此属性时可以定义 `setvalue`。
    - `setvalue: any = true` -> 要将 `set_flag` 指定的旗标设置成的值。
    - `once: boolean = false` -> 如果为 **true**，每个存档文件中只能与此事件交互一次。
    <br></br>如果为 **false**，可以随意与此事件交互任意次数。

    `cutscene`、`script` 和 `text` 互斥，因此一个可交互对象只能使用其中一个。

    ### 示例 [examples]
    ---
    #### 使用脚本 [using-an-script]
    按照[创建脚本教程](#making-scripts)操作，并将 `test_script` 添加到 `script` 自定义属性中。

    脚本是玩家走进后会立即触发的主世界 [`Event`](/wiki/api/Event)。

    - `temp: boolean = false` -> 脚本是否临时持久存在：即使 `once` 为 true 且脚本已经触发，脚本仍会显示。

    ## 存档点 [savepoint]
    ---

    这些星星可以让玩家**保存**游戏。

    要创建这个 [`Event`](/wiki/api/Event)，请在 `objects` 图层上定义一个**点**或**单瓦片区域**，并将其命名为 `savepoint`。

    存档点是 [`Interactable`](#interactable) 的子类，因此会继承它的所有自定义属性。

    这是该事件的属性：
    - `marker: string` -> 玩家在重新加载游戏或 Game Over 后从此存档点重生时所使用的标记名称。应该始终定义此属性。
    - `simple: boolean = Project configuration` -> 如果为 **true**，存档点会使用简单版本，即没有招募和储物功能，类似于第 1 章。
    <br></br>如果为 **false**，存档点会使用包含这两个选项的菜单。
    <br></br>默认情况下，它使用项目属性中 **mod.json** 文件所配置的值。
    - `text_once: boolean = false` -> 如果为 **true**，存档点只会在第一次交互时显示可交互文本。
    <br></br>如果为 **false**，存档点总是显示交互文本。
    - `heals: boolean = true` -> 如果为 **true**，队伍与存档点交互时会恢复生命值。
    <br></br>如果为 **false**，存档点不会治疗队伍。

    以下是存档点从可交互对象继承并修改的属性：
    - `solid: boolean = true` -> 存档点始终将此值设为 **true**，无法改变这一行为。
    - `text: string[]` -> 玩家与存档点交互时文本框中显示的文本。[查看该属性的教程](#text-tutorial)
    - `cutscene: string` -> 存档点不使用此属性，因此不要尝试定义它。
    - `script: string` -> 存档点不使用此属性，因此不要尝试定义它。
    - `setflag: string` -> 存档点不使用此属性，因此不要尝试定义它。
    - `setvalue: any = true` -> 存档点不使用此属性，因此不要尝试定义它。
    - `once: boolean = false` -> 存档点不使用此属性，因此不要尝试定义它。

    ## 过渡 [transitions]
    ---
    过渡对象允许玩家加载其他地图或商店。

    这个 [`Event`](/wiki/api/Event) 是一个 `area`，因此需要在 `objects` 图层上使用**矩形工具**创建，并将其命名为 `transition`。

    该事件拥有以下属性：
    - `map: string` -> 要将玩家传送到的地图名称。
    - `shop: string` -> 要将玩家传送到的商店名称。

    你可以选择过渡到地图或商店，因此只需在自定义属性中定义其中一个。
    - `x: number` -> 玩家在地图中重生位置的 x 坐标。
    - `y: number` -> 玩家在地图中重生位置的 y 坐标。
    - `marker: string = spawn` -> 玩家重生位置的标记名称。

    你可以定义 x、y 坐标，也可以定义玩家要重生到的标记。后者是更好的选择。如果两者都没有定义，那么玩家会在新地图中定义了 `spawn` 的情况下重生在 **spawn** 标记处。

    - `facing: string` -> 玩家在新地图重生时面朝的方向。可以是 `left`、`right`、`up` 或 `down`。
    - `sound: string` -> 玩家激活此过渡时可选的播放音效。
    - `pitch: number` -> 进入音效播放时的音高。
    - `exit_delay: number` -> 进入新地图后播放离开音效前额外等待的时间，单位为秒。
    - `exit_sound: string` -> 玩家进入新地图时可选的播放音效。
    - `exit_pitch: number` -> 离开音效播放时的音高。

    ## 摄像机目标 [camera-target]
    ---

    这是一个主世界区域 [`Event`](/wiki/api/Event)，玩家位于其中时会让摄像机对准指定位置。
    这在你希望玩家关注某个特定对象时很有用。

    这个事件是一个 `area`。在地图的 `objects` 图层上将对象命名为 `cameratarget`，即可创建此事件。

    该事件的可配置属性：
    - `x: number` -> 摄像机需要聚焦的位置的 x 坐标。
    - `y: number` -> 摄像机需要聚焦的位置的 y 坐标。
    - `marker: string` -> 指示摄像机需要聚焦位置的标记名称。

    建议**使用标记**而不是直接填写 x、y 值，因为这样更简单，也可以在 Tiled 中移动标记。

    - `lockx: boolean = true` -> 如果为 **true**，摄像机的 x 位置会锁定到目标位置。
    <br></br>如果为 **false**，摄像机可以沿 x 轴自由移动。
    - `locky: boolean = true` -> 如果为 **true**，摄像机的 y 位置会锁定到目标位置。
    <br></br>如果为 **false**，摄像机可以沿 y 轴自由移动。

    如果想偏移摄像机而不是简单地将其锁定在某处，这些属性就很有用。

    - `speed: number = 16` -> 摄像机移动到目标位置的速度。
    - `returnspeed: number = 16` -> 摄像机返回原始目标（通常是玩家）的速度。
    - `time: number = 0.25` -> 摄像机移动到目标位置所需的时间，单位为秒。
    - `returntime: number = 0.25` -> 摄像机返回原始目标（通常是玩家）所需的时间，单位为秒。

    你可以使用 **speed** 或 **time** 来决定摄像机如何移动到目标位置，不要同时使用两者，因为 **time** 的优先级高于 **speed**。

    如果都没有提供，则会使用摄像机默认值：speed 为 16，time 为 0.25。

    - `solid: boolean = true` -> 如果为 **true**，力场是实心的，玩家无法穿过它。
    <br></br>如果为 **false**，玩家可以穿过力场。
    - `visible: boolean = false` -> 如果为 **true**，玩家始终可以看到力场。
    <br></br>如果为 **false**，玩家只有靠近对象时才能看到力场。
    - `flag: string` -> 用于检查力场是否激活的旗标名称。如果旗标开头有 `!`，检查结果会反转。
    - `inverted: boolean = false` -> 如果为 **true**，旗标检查会反转；当 `flag == value` 时，力场会**未激活**。
    <br></br>如果为 **false**，当 `flag == value` 时，力场会**激活**。
    - `value: boolean = true` -> 力场激活时 `flag` 应该具有的值。

    ### 示例 [example]
    ---
    由于我们还没有制作谜题，可以使用[设置旗标事件](#set-flag-event)或调试旗标编辑器来测试力场功能。

    ## 传送门 [warp-door]
    ---

    传送门是允许玩家在主世界位置之间**快速旅行**的对象。

    要创建这个 [`Event`](/wiki/api/Event)，请在 `objects` 图层上放置一个点，并将其命名为 `warpdoor`。

    该事件的自定义属性如下：
    - `open: boolean = true` -> 如果为 **true**，传送门处于打开状态，玩家可以与它交互并快速旅行。
    <br></br>如果为 **false**，只会显示门框，玩家无法快速旅行。
    - `openflag: string` -> 用于检查传送门是否打开的旗标名称。该旗标必须是布尔值。

    - `name: string[]` -> 每张可用地图在传送选择中显示的名称列表。
    - `marker: string[]` -> 传送门将玩家传送到的标记名称列表。
    - `flag: string[]` -> 用于判断是否可以传送到某张地图的旗标列表。例如，你可以允许玩家在项目进行到一半时快速旅行，但不允许前往之后的地点。

    ## 推动方块 [push-block]
    ---
    推动方块通常用于制作谜题。要创建这个 [`Event`](/wiki/api/Event)，请在 `objects` 图层上放置一个只覆盖**一个瓦片**的 `area`，并将其命名为 `pushblock`。

    要定义推动方块可以和不可以移动的边界，需要创建一个新的 `blockcollision` 图层。
    在此图层中定义可推动方块的碰撞，玩家不会受到这些碰撞的影响。
    更多信息请查看示例。

    还应该使用另一种地面，让玩家知道方块移动的边界在哪里。

    该事件的可配置属性如下：
    - `sprite: string` -> 方块可选的自定义精灵，用于替代普通精灵。<br></br>
    如果想使用普通精灵，则不需要设置此属性。
    - `solvedsprite: string` -> 方块进入已解状态时可选的自定义精灵。<br></br>
    当方块位于[瓦片按钮](#tile-button)上方时会自动更新。
    - `pushdist: number = 40` -> 方块每次被推动时移动的像素数。40 像素等于一个瓦片，但具体数值取决于地图的瓦片宽度和高度。
    - `pushtime: number = 0.2` -> 推动方块时它移动所需的时间，单位为秒。
    - `pushsound: string = "noise"` -> 推动方块时播放的音效名称。
    - `pressbuttons: boolean = true` -> 此属性**未使用**。
    - `lock: boolean = false` -> 如果为 **true**，方块进入已解状态后会锁定在原地（也就是方块位于[瓦片按钮](#tile-button)上方时）。
    <br></br>如果为 **false**，即使方块位于[瓦片按钮](#tile-button)上方，也可以移动。根据谜题的复杂程度，你可能更喜欢这种行为。
    - `inputlock: boolean` -> 如果为 **true**，推动方块时玩家会被锁定在原地。
    <br></br>如果为 **false**，即使推动方块，玩家也可以移动。
    <br></br>如果计划制作复杂谜题，请将其设置为 false，以避免不必要的停顿。
    <br></br>默认值在项目配置文件的 `pushBlockInputLock` 属性中定义。

    我们可以走出房间来重置谜题，但为什么不创建一个按钮来重置谜题呢？

    我会创建一个自定义事件来实现这一点，但其实也可以直接使用[瓦片按钮](#tile-button)！
    （之后我甚至会用瓦片按钮替换这个自定义事件。）

    这是我创建的事件。

    ```lua
    --- 玩家踩上时重置推动方块谜题的自定义事件
    ---@class ResetButton : Event
    local ResetButton, super = Class(Event)

    ---创建重置按钮事件
    ---@param x number 按钮的 x 坐标
    ---@param y number 按钮的 y 坐标
    ---@overload fun(x : number, y: number) : ResetButton
    function ResetButton:init(x, y)

        super.init(self, x, y, 40, 40)

        self.idle_sprite = "world/events/glowtile/idle"
        self.pressed_sprite = "world/events/glowtile/pressed"

        self:setSprite(self.idle_sprite, 1/8)
    end

    ---玩家进入此事件时调用
    ---@param player Player 进入事件的角色
    function ResetButton:onEnter(player)
        --- 确保事件只对玩家（Kris）作出反应
        if player.is_player then
            self:setSprite(self.pressed_sprite)
            Assets.playSound("noise")
            Assets.playSound("him_quick")

            -- 获取当前场景中的所有 PushBlock 并重置它们
            for _, pushblock in ipairs(Game.stage:getObjects(PushBlock)) do
                pushblock:reset()
            end
            -- 在方块重置时阻止玩家移动，
            -- 否则玩家可能会走到方块应该到达的位置，
            -- 并卡在碰撞中。
            Game.lock_movement = true
            Game.world.timer:after(.4, function ()
                Game.lock_movement = false
            end)

        end
    end

    ---玩家离开此事件时调用
    ---@param player Player 离开事件的角色
    function ResetButton:onExit(player)
        --- 确保事件只对玩家（Kris）作出反应
        if player.is_player then
            self:setSprite(self.idle_sprite, 1/8)
        end
    end
    ```

    ## 瓦片按钮 [tile-button]
    ---
    一种可以被角色或[推动方块](#push-block)压下的按钮。

    要创建这个 [`Event`](/wiki/api/Event)，请在 `objects` 图层上放置一个单瓦片大小的 `area`，并将其命名为 `tilebutton`。

    该事件的可配置属性如下：
    - `sprite: string` -> 可选的自定义精灵，用于替代普通的**未按下**精灵。
    - `pressedsprite: string` -> 按钮**按下**时使用的可选自定义精灵，用于替代普通精灵。
    - `onsound: string` -> 有东西踩到按钮时使用的音效。
    - `offsound: string` -> 按钮不再被按下时使用的音效。
    - `blocks: boolean = false` -> 如果为 **true**，此瓦片按钮**只能由**[推动方块](#push-block)激活。
    <br></br>如果为 **false**，此瓦片按钮**只能由**[NPC](#npc)、[玩家](/wiki/api/Player)和[跟随者](/wiki/api/Follower)激活。
    - `group: string|number` -> 用于将同一房间中的多个按钮分组。只有当同组按钮都被**同时按下**时，它们才会被设置为**完成/已解**状态。
    <br></br>它类似于 ID，因此同一组中的每个按钮都需要拥有相同的 group 值。
    - `flag: string` -> 当按钮组解开时设置为 **true**，谜题不再处于解开状态时设置为 **false** 的旗标名称。
    此旗标会作为**全局旗标**保存。
    - `once: boolean = false` -> 如果为 **true**，每个存档文件中只能完成一次这个按钮的谜题。这意味着谜题解开后，游戏不再检查它是否完成，`flag` 也不会被设置为 **false**。大多数情况下你会更喜欢这种行为。
    <br></br>如果为 **false**，当谜题**不再处于**已解状态时，`flag` 会被设置为 **false**。
    - `keepdown: boolean = false` -> 如果为 **true**，即使按住按钮的对象移开，按钮仍会保持按下状态。
    <br></br>如果为 **false**，按住按钮的对象移开后，按钮会恢复为未按下状态。
    - `cutscene: string` -> 按钮谜题解开时应播放的过场动画名称。
    - `script: string` -> 按钮谜题解开时应执行的脚本文件名称。

    ### 示例 [examples]
    ---

    属性确实很多，所以接下来通过一些示例和视频来帮助你理解这个事件的工作方式。

    你应该先完成[推动方块](#push-block)教程中的谜题，因为我们会在本例中完成它。

    首先创建 `script`。在 `scripts/world/scripts` 中创建一个新的 .lua 文件，我把它命名为 `reset_puzzle.lua`。

    这是我创建的脚本。

    ```lua
    ---重置房间中的所有推动方块谜题
    ---@param event TileButton 执行此脚本的事件
    return function(event)
        -- 由于我们是从瓦片按钮调用此脚本的，所以只会得到 event

        -- 这样可以让跟随者无法激活瓦片按钮，只有玩家可以激活
        -- 不能通过属性配置这一点，因为 `blocks` 属性只表示按钮是否可以由
        -- 玩家和跟随者激活，而不是二选一。
        event.npc_activated = false
        Assets.playSound("noise")
        Assets.playSound("him_quick")
        -- 获取当前场景中的每个 PushBlock，并将其重置为默认状态
        for _, pushblock in ipairs(Game.stage:getObjects(PushBlock)) do
            pushblock:reset()
        end

        -- 在方块重置时阻止玩家移动；否则玩家可能会走到方块应该到达的位置，
        -- 并卡在碰撞中。
        Game.lock_movement = true
        Game.world.timer:after(.4, function ()
            Game.lock_movement = false
        end)
    end
    ```

    ## 切换控制器 [toggle-controller]
    ---
    这个 [`Event`](/wiki/api/Event) 是一种**控制器**，用于切换主世界中其他事件的存在状态。

    此控制器会在其旗标**发生变化时立即**切换其他事件的存在状态，因此不需要重新加载房间就能激活或停用其他事件。

    此事件创建在 `controllers` 图层中。本例会使用<span style={{color: "#ffc800"}}>金色。#ffc800 (255, 200, 0)</span>来表示该图层。

    ![](/wiki/toggle_controller_tutorial_1.png)

    要创建此事件，请在 `controllers` 图层上放置一个 `point`，并将其命名为 `toggle`。

    这是此控制器的自定义属性：
    - `flag: string` -> 用于检查目标是否应处于激活状态的旗标名称。如果旗标开头有 `!`，检查结果会反转。
    控制器会先尝试将此旗标作为**全局旗标**获取，如果找不到，再尝试将其作为**地图旗标**获取。
    - `inverted: boolean = false` -> 如果为 **true**，旗标检查会反转；当 `flag == value` 时，目标会处于**未激活**状态。
    <br></br>如果为 **false**，当 `flag == value` 时，目标会处于**激活**状态。
    - `value: boolean = true` -> 目标激活时 `flag` 应该拥有的值。如果未提供，控制器会检查 `if flag == true`。
    - `target: (Character|Event|Collider)[]` -> 此控制器所**附着**并负责开关的**对象**列表。

    等等……`(Character|Event|Collider)[]` 是什么意思？简单来说，target 是控制器可以切换的对象数组，这些对象可以是事件（包括 NPC 等其他角色），也可以是地图中的碰撞体。

    那么在 Tiled 中要如何创建这个属性？我们需要使用一种之前还没用过的 **Tiled 类型**：`object` 类型。

    ![](/wiki/toggle_controller_tutorial_2.png)

    由于 target 是一个 `array`，我们可以像[多个文本框教程](/wiki/using-events#multiple-textboxes)中定义 text 属性那样定义它。

    按照下面的方式创建目标：`target1`、`target2`、`target3`、`target4`、`target5`、……、`targetN`。**targetN** 表示目标数量不限。

    下图展示了如何将地图中的对象链接到该属性。

    ## NPC [npc]
    ---
    NPC 是 [Character](/wiki/api/Character) 的扩展，可以像事件一样放置在地图上。

    在地图的 `objects` 图层上将对象命名为 `npc`，即可创建 NPC。

    该事件的可配置属性如下：
    - `actor: string` -> 此 NPC 使用的 actor ID。
    - `sprite: string` -> NPC 待机时应使用的精灵名称。
    - `animation: string` -> NPC 待机时应使用的动画名称。

    必须定义 actor。NPC 会使用 actor 属性中定义的待机精灵或待机动画。
    待机精灵是 `self.default_sprite`，待机动画是 `default_anim`，也可以使用 `self.default`。
    如果希望 NPC 使用不同于 actor 数据中定义的精灵或动画作为默认值，可以定义 `sprite` 或 `animation`。

    - `facing: string = "down"` -> NPC 默认面朝的方向。可以是 `up`、`down`、`right` 或 `left`。
    - `turn: boolean = false` -> 如果为 **true**，与 NPC 交互时 NPC 会转向玩家。
    <br></br>如果为 **false**，NPC 始终面朝 `facing` 中定义的方向。

    如果启用 turn，请确保 NPC 使用的精灵是**面向精灵**。我会使用[追逐敌人](#chaser-enemy)中的相同教程，解释什么是面向精灵。

    先停下来说明一下，所谓面向精灵是什么意思？我们以 Kris 的精灵为例。前往 Kristal 中的 `assets/sprites/party/kris/dark` 文件夹。
    <br></br>查看 `walk` 文件夹，可以看到四个方向 `left`、`right`、`up` 和 `down` 都有对应的精灵。
    <br></br>因此，如果创建一个 **actor 为 kris 的 NPC**，就可以设置 `facing`，游戏会根据它的值使用这四个精灵中的一个。
    但不需要为此创建单独的文件夹。游戏检查精灵是否为面向精灵时，会使用两种分隔符 **\_** 和 **\/**。
    所以，你可以将精灵定义为 **animation`_`direction**，例如 **walk_down**、**walk_up**、**walk_left** 和 **walk_right**；
    也可以创建一个以**精灵名称**命名的文件夹，将精灵放入其中，并将它们命名为 **left**、**right**、**up** 和 **down**。

    - `talk: boolean = true` -> 如果为 **true**，NPC 被交互并开始输入对话时会播放说话动画。
    <br></br>如果为 **false**，NPC 不会播放此动画。示例中会对此进行说明。
    - `talksprite: string` -> NPC 说话时使用的说话精灵名称。
    将其设置为希望说话时使用的精灵名称，就能替代默认精灵。
    - `solid: boolean = true` -> 如果为 **true**，NPC 是实心对象，玩家无法穿过它。
    <br></br>如果为 **false**，玩家可以穿过 NPC。
    - `cutscene: string` -> 与 NPC 交互时要启动的过场动画名称。
    记得使用 **group.cutscene** 的格式。
    - `script: string` -> 与 NPC 交互时要运行的脚本文件名称。
    - `text: string[]` -> 与 NPC 交互时显示的文本。工作方式与[文本教程](#text-tutorial)中的相同。

    不要在同一个 NPC 中同时使用 `script`、`cutscene` 和 `text`，只能使用其中一个。

    - `setflag: string` -> 玩家交互时要设置为 `setvalue` 的旗标名称。
    使用此属性时可以定义 `setvalue`。
    - `setvalue: any = true` -> 要将 `set_flag` 指定的旗标设置成的值。
    - `path: string` -> NPC 要沿着移动的路径形状名称。参考[路径系统教程](#path-system-tutorial)。
    - `speed: number = 6` -> 如果定义了 `path`，NPC 沿指定路径移动的速度。可以是浮点数。
    - `progress: number = 0` -> 如果定义了 `path`，NPC 沿路径移动的初始进度，以 0 到 1 之间的小数表示。
    0 表示路径起点，1 表示路径终点。可以是浮点数。

    ## 追逐敌人 [chaser-enemy]
    ---
    追逐敌人是你在主世界中遇到、碰撞后会开始一场遭遇战的敌人。
    这是一个复杂的事件，希望本教程能帮助你在项目中实现敌人。

    追逐敌人不是 [`Event`](/wiki/api/Event) 的扩展，而是 [`Character`](/wiki/api/Character) 的扩展，但创建方式和事件一样。
    要创建敌人，请在 `objects layer` 上放置一个 `point` 或 `one tile area`，并将其命名为 `enemy`。

    该对象的可配置属性如下：
    - `actor: string` -> 此敌人的 actor ID，用于在地图中显示敌人。如果不想项目崩溃，请定义此属性。
    - `sprite: string` -> 此敌人使用的精灵，替代 actor 数据中定义的默认精灵。
    - `animation: string` -> 此敌人使用的动画，替代 actor 数据中定义的默认动画。
    - `facing: string` -> 如果拥有面向精灵，此敌人的面朝方向。可以是 `left`、`right`、`up` 或 `down`。

    先停下来说明一下，所谓面向精灵是什么意思？我们以 Kris 的精灵为例。前往 Kristal 中的 `assets/sprites/party/kris/dark` 文件夹。
    <br></br>查看 `walk` 文件夹，可以看到四个方向 `left`、`right`、`up` 和 `down` 都有对应的精灵。
    <br></br>因此，如果创建一个 **actor 为 kris 的敌人**，就可以设置 `facing`，游戏会根据它的值使用这四个精灵中的一个。
    但不需要为此创建单独的文件夹。游戏检查精灵是否为面向精灵时，会使用两种分隔符 **\_** 和 **\/**。
    所以，你可以将精灵定义为 **animation`_`direction**，例如 **walk_down**、**walk_up**、**walk_left** 和 **walk_right**；
    也可以创建一个以**精灵名称**命名的文件夹，将精灵放入其中，并将它们命名为 **left**、**right**、**up** 和 **down**。

    - `encounter: string` -> 玩家与敌人碰撞时会触发的遭遇战 ID。存放在 `scripts/battle/encounters` 中。
    - `enemy: string` -> 此敌人要使用的敌人 ID。存放在 `scripts/data/actors` 中。
    <br></br>等等……既然已经定义了 `actor`，为什么还需要定义 `enemy`？我也不太清楚，但可以告诉你它们分别做什么。
    **actor** 用于主世界中的精灵，以及切换到战斗时使用；而 **enemy** 会与 actor 一起添加到切换进入战斗的敌人列表中。
    - `group: string` -> 可以分配给多个敌人的任意 ID，用来将它们编为一组。因此玩家完成这场遭遇战后，该组中的所有敌人都会从地图中卸载。
    - `path: string` -> 敌人要沿着移动的路径形状名称。参考[路径系统教程](#path-system-tutorial)。
    - `speed: number = 6` -> 如果定义了 `path`，敌人沿指定路径移动的速度。可以是浮点数。
    - `progress: number = 0` -> 如果定义了 `path`，敌人沿路径移动的初始进度，以 0 到 1 之间的小数表示。
    0 表示路径起点，1 表示路径终点。可以是浮点数。
    - `chase: boolean = false` -> 如果为 **true**，敌人发现玩家时会追逐玩家。
    <br></br>如果为 **false**，敌人在任何情况下都不会追逐玩家。
    - `chasing: boolean = false` -> 如果为 **true**，敌人在玩家进入房间时就会立即开始追逐。
    <br></br>如果为 **false**，敌人会按照其他属性中的配置移动。
    - `chasedist: number = 200` -> 敌人可以看到玩家的距离，单位为像素。
    因此，当玩家与敌人之间的距离小于 `chasedist` 时，如果 `chase` 为 true，敌人就会开始追逐玩家。
    - `chasetype: string = linear` -> 敌人追逐玩家的方式。该属性有以下可选值：
        - `linear` -> 敌人以恒定速度追逐玩家，除非设置了 `chaseaccel`。在这种情况下，速度会在每帧乘以加速度。
        - `multiplier` -> 敌人的速度会随追逐玩家的时间呈指数增长。
        - `flee` -> 敌人会以与 linear 相同的速度**逃离**玩家。

    如果还不明白 `linear` 和 `multiplier` 的区别，不用担心。你只需要知道，使用 `multiplier` 追逐类型时，敌人的追逐速度会快得多地增加。

    - `chasespeed: number = 9` -> 敌人追逐玩家时的速度，单位是 30FPS 下每帧的像素数。
    - `chaseaccel: number` -> 敌人追逐玩家时的加速度。在 `linear` 模式下，速度每帧乘以加速度；
    而在 `multiplier` 模式下，速度每帧乘方于加速度。
    - `chasemax: number` -> 敌人追逐玩家时的最大速度，只有同时设置了 `chaseaccel` 时才会生效。

    如你所见，追逐机制有点复杂，因此我会通过一些示例让它们更容易理解。这套机制使用了 `enemycollision` 图层，
    具体内容会在示例中介绍。

    - `once: boolean = false` -> 如果为 **true**，敌人的遭遇战**完成后**就不会再生成。
    <br></br>如果为 **false**，房间加载时仍会生成敌人，即使你已经完成过它的遭遇战。
    - `aura: boolean` -> 如果为 **true**，敌人周围会有光环，就像第 2 章中的敌人一样。
    <br></br>如果为 **false**，敌人周围不会有光环。
    <br></br>默认值在项目的**配置文件**中的 **enemyAuras** 属性里设置。

    - `pacetype: string` -> 敌人不追逐玩家时所使用的巡游方式。该属性有以下可选值：
        - `wander` -> 按固定顺序在敌人生成点与多个标记之间巡游。
        - `randomwander` -> 随机在敌人生成点与多个标记之间巡游。
        - `verticalswing` -> 沿 y 轴的正弦波移动，也就是上下移动。
        - `horizontalswing` -> 沿 x 轴的正弦波移动，也就是左右移动。

    根据想使用的 pacetype，会有一些专门定义其行为的属性。

    如果使用 **wander** 或 **randomwander**：
    - `marker: string[]` -> 敌人要在其间移动的标记列表。使用 `wander` 时按顺序移动，使用 `randomwander` 时随机移动。
    <br></br>由于此属性是字符串数组，必须使用 `marker1`、`marker2`、`marker3`、……、`markerN` 定义它。每个 marker 的值就是对应标记的名称。
    - `paceinterval: number = 24` -> 敌人在每个标记处停留、然后前往下一个标记前等待的帧数。
    - `pacereturn: boolean = true` -> 如果为 **true**，敌人每次到达标记后都会返回生成点。
    <br></br>如果为 **false**，敌人会继续前往下一个标记，而不是返回生成点。
    - `pacespeed: number = 2` -> 敌人巡游时的移动速度。

    如果使用 **verticalswing** 或 **horizontalswing**：
    - `swingdiv: number = 24` -> 敌人摆动速度的除数（数值越大，速度越慢）。
    - `swinglength: number = 400` -> 敌人摆动覆盖的总长度，单位为像素。敌人的起始位置是这条线的中心。

    好了，信息很多。现在通过一些示例来理解这个对象的工作方式。
